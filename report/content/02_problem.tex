\section{Постановка задачи}

\subsection*{Лабораторная работа №1. Представления}
\begin{enumerate}
    \item Создать представление.
    \item Выполнить простой запрос к созданному представлению.
    \item Выполнить сложный запрос с присоединением к представлению других таблиц.
\end{enumerate}

\subsection*{Лабораторная работа №2. Триггеры}
\begin{enumerate}
    \item создать таблицу для хранения сводной информации о количестве поселений и платежей каждого студента;
    \item реализовать триггеры для автоматического изменения сводной информации при добавлении, изменении и удалении записей в таблицах \texttt{student}, \texttt{settlement} и \texttt{payment};
    \item проверить корректность работы триггеров и автоматическое обновление сводной таблицы при изменении связанных данных.
\end{enumerate}

\subsection*{Лабораторная работа №3. Управление доступом}
\begin{enumerate}
    \item создать пользователя, имеющего доступ только на чтение сводной таблицы \texttt{student\_settlement\_payment\_counts};
    \item создать пользователя, управляющего таблицами \texttt{student}, \texttt{settlement} и \texttt{payment}, изменение которых активирует триггеры;
    \item проверить, что изменения, выполненные вторым пользователем, видны первому пользователю в сводной таблице;
    \item продемонстрировать запросы, которые не выполняются ни у одного из пользователей.
\end{enumerate}

\subsection*{Лабораторная работа №4. Транзакции}
На примере двух параллельных транзакций показать наличие или отсутствие одной из аномалий параллельного выполнения на выбранном уровне изоляции.

Для демонстрации выбрано неповторяющееся чтение, которое возможно на уровне изоляции \texttt{READ COMMITTED}~\cite{pg-isolation}. Требуется проверить, что произойдёт, если одна транзакция дважды читает одну и ту же строку таблицы \texttt{payment}, а между этими чтениями другая транзакция изменяет эту строку и фиксирует изменение. Если результаты двух одинаковых запросов различаются, аномалия присутствует на данном уровне изоляции.

\subsection*{Лабораторная работа №5. Функции и процедуры}
\begin{enumerate}
    \item Реализовать функцию, которая принимает фамилию, имя и отчество студента, производит конкатенацию полей и возвращает одно поле с фамилией и инициалами.
    \item Реализовать процедуру регистрации заселения и связанного платежа. Процедура принимает данные студента и сотрудника, адрес здания, тип комнаты, этаж, даты заселения, способ и сумму оплаты, дату платежа. При выполнении процедуры:
    \begin{enumerate}[label=(\alph*)]
        \item найти студента по ФИО и паспортным данным; если запись отсутствует, добавить её; получить \texttt{student\_id};
        \item найти сотрудника по ФИО, паспортным данным и должности; если запись отсутствует, добавить её; получить \texttt{employee\_id};
        \item найти или добавить здание и тип комнаты, получив соответствующие идентификаторы;
        \item найти комнату по зданию и типу комнаты, а затем место по комнате и этажу; если записи отсутствуют, добавить их и получить идентификаторы;
        \item найти или добавить способ оплаты\newline
        и получить \texttt{payment\_method\_id};
        \item добавить заселение с полученными идентификаторами студента, сотрудника и места, затем добавить связанный с заселением платёж.
    \end{enumerate}
    \item Продемонстрировать работу функции на данных студентов, включая случаи с указанным и отсутствующим отчеством.
    \item Продемонстрировать работу процедуры для случаев, когда связанные записи отсутствуют, уже существуют или отсутствует только студент; проверить изменение счётчиков заселений и платежей в сводной таблице.
\end{enumerate}
